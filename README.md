# Local PDF Knowledge Assistant (RAG)

A basic retrieval-augmented chatbot using MiniLM embeddings, FAISS retrieval and local Ollama answers. This is a simple document RAG, without GraphRAG, agents or OCR. The separate `New folder` project is unchanged.

## Run (PowerShell)

```powershell
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
ollama pull llama3
# Start Ollama if it is not already running: ollama serve
python -m streamlit run app.py
```

Open the local URL printed by Streamlit. The embedding model downloads on first use, so internet is needed initially. Ollama must be installed separately and running with the selected model.

## Features

- Upload multiple text-based PDFs and UTF-8 TXT files together.
- Process documents explicitly, once per upload/settings change; reuse the index during chat.
- Cached embedding model, overlapping chunks and configurable chunk size/overlap.
- Configurable number of retrieved passages and Ollama model name.
- Chat history and recent conversation context for follow-up questions.
- Grounded answer prompt with numbered source references, file names and PDF page numbers.
- Expandable retrieved passages for checking answers.
- Indexed file list and passage count; clear chat, reset index and download chat as JSON.
- Validation for invalid overlap, empty/scanned files, indexing errors and Ollama errors.

The Streamlit index and chat live in the current browser session; reset/restart requires indexing again. Uploaded bytes are read in memory. TXT sources use page 1. Source citations are generated by the LLM and should be checked against the displayed passages. Summaries cover retrieved passages, not necessarily every page. Scanned PDFs need separate OCR. The answer prompt tells the model to treat document instructions as untrusted text.

The original CLI remains available: `python ingest.py` indexes `data/sample.pdf`, then `python chat.py` queries the saved index. Only load trusted local pickle files.

## Checks

```powershell
python -m unittest discover -s tests -v
```


CUDA troubleshooting: The app defaults to CPU inference (num_gpu=0), avoiding the GPU runner. CPU can be slower. Uncheck 'Use CPU' in the sidebar to try GPU; CUDA failures automatically retry once on CPU. Context is set to 4096 tokens and responses to at most 512 generated tokens.
